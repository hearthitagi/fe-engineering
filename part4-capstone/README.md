把前 11 周的能力固化成别人能用的东西，并证明它真的能扛故障。

| 章节 | 内容 | 产出 | 状态 |

| [P2 端到端演练](P2-端到端演练.md) | issue → 分支 → PR → 门禁 → 合并 → 镜像 → NAS → 验证 → 回滚 | 演练记录 | 初稿 |
| [P3 故障演练手册](P3-故障演练手册.md) | 10 个剧本：幽灵依赖、循环依赖、hash 失效、锁文件漂移、镜像过大、缓存头错误、部署半成功、健康检查误判、回滚失败、权限不足 | 排查路径 + 修复命令 | 初稿 |

## 怎么用

1. 先做 P1，把模板和生成器跑通；
2. 再做 P2，用一个真实的小功能走完 issue → PR → 镜像 → NAS → 回滚；
3. 最后做 P3，按剧本制造故障并修回；
4. 用附录 A 逐章验收，用附录 B 的速度查错。

## 完成标准

- 新人拿到模板仓库，30 分钟内能跑起来并提交第一个 PR
- 10 个故障剧本全部演练过，每个都能在 10 分钟内定位
- 仓库 README 能说清架构、约定、发布与回滚流程
